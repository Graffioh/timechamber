# References

Use this file for high-quality sources that materially support lessons,
checkpoints, corrections, or deep dives in this chamber.

Prefer primary papers, canonical books, official documentation, respected
courses, reputable technical blogs, model cards, and maintained reference
implementations. Avoid thin, unsourced, anonymous, or SEO driven sources. If a
new or niche source looks useful, add a short quality note explaining why it is
trustworthy enough to use.

Populate this file mostly when the chamber starts, based on the subject and
first lessons. After that, keep it alive: add sources that shape lessons,
replace weaker references when better ones are found, and ask for learner
feedback occasionally about which sources are most useful.

## Source Quality Rules

- Search the web when current, precise, or specialized facts matter.
- Prefer primary or famous references before secondary summaries.
- Record the source when it shapes a lesson or checkpoint.
- Replace weak or redundant sources when a better source fills the same role.
- Use learner feedback as lightweight ranking evidence.
- Keep notes short: what it supports, why it is reliable, and when to use it.
